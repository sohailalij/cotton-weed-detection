# 0004: Serve the 960 px model

Date: 30 October 2026
Status: accepted

## Context

After the first test run, errors were analysed by class, box size and camera. Small weeds looked like a weakness, so YOLO11s was retrained at 960 px input on split v1. Batch size was 8 instead of 16, and training took 2.0 hours instead of 1.1.

## Decision

Use the 960 px model as the primary model. Test mAP50 rose from 0.9055 to 0.9275 and mAP50-95 from 0.8439 to 0.8714. On validation, the one comparison not touched by test-set inspection, it also scored higher (mAP50 0.894 against 0.881), by a small margin from one run each.

## Consequences

- The gain is not what it first looks like. At matched confidence cutoffs the 960 px model finds about the same number of weeds as the 640 px model (recall within one point) but makes roughly 200 fewer false detections, and detection F1 is 5 to 6 points higher.
- There is no evidence that it helps small weeds. It fails slightly more often on boxes under 64 px.
- About 84% of the summed mAP50 gain comes from six rare classes with about 50 test boxes or fewer, so it should not be read as a general 2-point improvement.
- CPU latency in PyTorch is about 38% higher (346.6 ms against 252.1 ms median).
- The test set was used to guide this experiment, so the final test number is not a completely untouched estimate. `docs/evaluation.md` says this too.
- The 640 px model remains the fallback if latency on the hosting tier is a problem.
